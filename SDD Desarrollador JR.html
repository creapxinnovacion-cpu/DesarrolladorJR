1Introducción y Marco Operativo

1.1Propósito del Documento

Este Software Design Document (SDD) establece la especificación técnica formal de los sistemas diseñados, codificados y desplegados por el Desarrollador JR dentro del equipo de CreaPx. Define las decisiones arquitectónicas, modelos de datos, protocolos criptográficos y reglas de negocio tributarias vigentes en El Salvador.

1.2Alcance de Ingeniería

Abarca diez módulos operativos en producción que resuelven necesidades de automatización administrativa, emisión de Documentos Tributarios Electrónicos (DTE), digitalización con OCR, gestión hospitalaria, inventarios con valoración contable, y rastreo logístico satelital.

1.3Glosario Técnico y Normativo

DTE
Documento Tributario Electrónico homologado por el MH de El Salvador.
MH / DGII
Ministerio de Hacienda / Dirección General de Impuestos Internos.
F-07 / Anexo 3
Informe mensual de IVA y retenciones en formato plano CSV de 21 columnas.
JWS RS512
Firma digital en JSON Web Signature con par de claves RSA de 4096 bits y SHA-512.
FEFO / PEPS
First Expired, First Out (Físico) / Primeras Entradas, Primeras Salidas (Contable).
QThread
Procesamiento multihilo asíncrono en Qt/PySide6 desacoplado de la UI.

3.3Principios de Ingeniería

  • 1. La norma legal manda Las validaciones tributarias de Hacienda (El Salvador) y de la DGII se aplican a nivel de código con librerías de precisión arbitraria (BCMath) para evitar errores de redondeo financiero.
  • 2. Tolerancia a fallos y resiliencia offline Ningún fallo de red externa debe detener las ventas de un cliente. Los sistemas implementan búferes locales (Dexie/SQLite) con reintentos automáticos.
  • 3. Separación estricta de responsabilidades Arquitecturas desacopladas (Domain-Driven / Feature-Based en FastAPI, MVC en Express, BLoC en Flutter) que garantizan mantenibilidad.
  • 4. Entornos de desarrollo reproducibles Configuraciones en Docker Compose y manifiestos Kustomize para que el entorno local replique exactamente producción.

4.2Pipeline de Ciclo de Vida del DTE (Facturación Electrónica)

  1. 1. Captura & POS Frontend en React o Flutter estructura el ítem, cantidades, precios brutos y datos del receptor.
  2. 2. Cálculo Exacto Laravel calcula IVA 13%, retenciones 1% y percepciones usando precisión arbitraria con BCMath.
  3. 3. Firma JWS RS512 Microservicio Spring Boot genera el token JWS compacto utilizando la clave privada RSA de Hacienda.
  4. 4. Transmisión a MH Envío REST al endpoint oficial de Hacienda. Recepción del sello de recepción oficial y código QR.
  5. 5. Entrega & Archivo Generación de representación gráfica PDF y envío automatizado del JSON firmado al cliente por email.
Mecanismo de Contingencia: En caso de indisponibilidad de la red o del servidor del Ministerio de Hacienda, el documento se resguarda en el almacenamiento local encriptado y se despacha automáticamente mediante transmisión en lote una vez restablecida la conexión.

Arquitectura multi-tenant para empresas, usuarios y asignación de roles contables.

  • Empresa (id, nit, razon_social, estado)
  • Usuario (id, email, hashed_password, is_admin)

Ocho hojas estructuradas con llaves foráneas y auditoría estricta de movimientos.

  • PRODUCTOS (id, nombre, stock_minimo)
  • LOTES (id, producto_id, fecha_vencimiento)
  • MOVIMIENTOS (id, tipo, lote_id, costo_unitario)
  • AUDITORIA (timestamp, operador, accion)

Libro Compras F-07 Anexo 3 DGII

Estructura plana normalizada de 21 columnas sin encabezados requerida por Hacienda.

  • Col E: NIT o NRC (Exclusividad validada)
  • Col G - O: Desglose de Gravadas, Exentas y No Sujetas
  • Col P: DUI (Si aplica a persona natural)
  • Col Q - T: Operación, Clasificación y Sector

8Infraestructura, DevOps & Despliegue

8.1Estrategia de Contenedorización

Los microservicios de backend y frontend cuentan con archivos Dockerfile optimizados mediante compilaciones multi-etapa (*multi-stage builds*), reduciendo el peso final de las imágenes y minimizando la superficie de ataque. 

# Ejemplo de Despliegue con Docker Compose
version: '3.8'
services:
  fastapi-api:
    build: .
    ports:
      - "10000:10000"
    environment:
      - DATABASE_URL=${DATABASE_URL}
      - SECRET_KEY=${SECRET_KEY}
    restart: always

8.2Integración y Entrega Continua (CI/CD)

Flujos automáticos configurados en GitHub Actions que ejecutan linters, chequeos de formato, pruebas unitarias para cuadratura de IVA y compilación de artefactos antes de desplegar en Vercel (Frontends) y Neon/Render (Backends).

Pipelines Activos
  • GitHub Actions CI
  • Vercel Edge Deployment
  • Neon Serverless Branching
  • Kustomize K8s Manifests
